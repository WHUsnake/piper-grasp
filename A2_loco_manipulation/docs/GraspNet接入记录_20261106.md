# GraspNet 候选替换记录（2026-11-06）

已替换本目录 `grasp_generation` 的默认候选后端；保持目标点云输入和现有 `GraspCandidateArray` 接口，复用现有 planner 的预抓取计算。没有启动驱动、CAN、底盘或实机任务。

## 实现范围

- `src/manipulation/grasp_generation/grasp_generation/node.py` 默认 `backend=graspnet`；`backend=pca` 可作对照。单进程只发布一个后端，不在失败时自动回退 PCA。
- ROS 节点使用稳定 ROS Python，独立持久 worker 使用 `search-grasp2/.venv-graspnet`。模型只加载、校验、预热一次。源码 commit 和 checkpoint SHA256 在加载时检查；CUDA 不可用则启动失败，不生成替代候选。
- 输入 `/perception/target_cloud`。保持原始 frame/stamp，在该时间查询 base_link TF。水平进近与水平闭合各允许偏差 25°，都在基座系检查。只对目标云推理，没有增加场景云依赖或宣称完整碰撞检测。
- 开口过滤、相对模型分排序、位姿 NMS 后最多保留 12 个。保留 0.10 m 预抓取距离和 0.12 m 抬升字段；没有改动执行器的闭合控制。
- 推理在线程中运行，ROS 回调不等待 CUDA；只保留一份最新待处理点云。输入、排队、推理结果和已发布缓存都检查 0.5 s 年龄。目标身份变化、无效输入、TF 缺失、模型错误、过期都清空候选，原始采集时间不改写。
- `/grasp/diagnostics` 是 JSON String，含耗时、过滤原因、原始候选索引、depth、预测/输出宽度与 TCP 标定状态。

## 参考点与预抓取

原生轴到项目轴：`R_project = R_native @ [[0,0,1],[0,1,0],[-1,0,0]]`。

原生手指前端沿 X 位于 `depth`。当前明确使用可配置的预览假设：PiPER TCP 在指尖后方 `tcp_from_tip_m=0.03` m，因此：

```
p_cloud_TCP = translation + R_native[:,0] * (depth - tcp_from_tip_m)
p_cloud_pregrasp = p_cloud_TCP - R_project[:,2] * 0.10
```

**0.03 m 是未实物标定的预览假设，不是 PiPER 已测尺寸。** 必须用真实手指有效夹持区与现有 0.105 m TCP 的关系校准。`tcp_geometry_verified=false`。link6 到 TCP 的 0.105 m 变换仍由既有 planner 应用，候选生成器不重复扣除。

候选标为 `graspnet_baseline_preview`。pipeline 拒绝 GraspNet 的 `execute=true`；统一 arm adapter 拒绝对此类预览执行 enable/start。底盘互锁、反馈年龄、接触阈值不变。当前只完成候选和预抓取参数接入，不代表完整抓取/进近路径验收。

## 构建与使用

配置：`src/manipulation/grasp_generation/config/graspnet.json`，包含本机独立 Python、源码和权重绝对路径。换机器必须替换这些路径并验证 CUDA，不能直接复制本机路径。

构建（只构建消息包与候选包，不启动任何硬件）：

```bash
cd /home/xubo/桌面/she/A2_loco_manipulation
scripts/graspnet/build.sh
source /opt/ros/humble/setup.bash
source workspaces/graspnet/install/setup.bash
```

在已确认仅有一个候选 publisher 的预览环境中启动候选节点：

```bash
ros2 run grasp_generation grasp_generator
# PCA 对照，需先停止上述节点：
ros2 run grasp_generation grasp_generator --ros-args -p backend:=pca
```

节点需要输入点云和采集时刻 TF；GraspNet 启动时先预热。不要与旧的 grasp_generator 并行启动。

`src/bringup/robot_bringup/launch/pipeline.launch.py` 已改为默认 GraspNet，并暴露 `grasp_backend`、`graspnet_config` 参数。但本 A2 源树没有完整 robot_bringup 包构建文件，也没有 robot_planner/task_executor 源包。隔离 overlay 只安装 grasp_msgs 与 grasp_generation；本机其它工作区的已安装 pipeline 不会自动改变。部署时必须确认真实运行前缀，再将此 launch 纳入其维护源并重建。历史快照和 search-grasp2 的主链路本次没有修改，也没有声称机载部署已切换。
