# A2 看到瓶子后靠近并抓取：使用说明

> 更新：按用户要求保留原底盘服务，新增现场监督的两段入口。当前操作请先读 [两步操作](两步操作.md)。本文中的独占模式及候选驱动说明不等于监督模式；没有删除原有独占检查。

更新：2026-10-28。操作对象为机载 `/home/unitree/A2_loco_manipulation`，参考来源为 `/home/unitree/a2_piper_project`。下面机器人命令均在 SSH 登录后的机载终端执行。

## 1. 先明确现在能做到哪一步

目标流程是：**识别并锁定瓶子 → 靠近同一瓶子 → 验证底盘停稳 → 获取新观测 → 规划 → 执行一次抓取 → 持物保持。**

**当前还不能用一条命令完成真实“搜索＋靠近＋抓取”。** 统一命令已经部署，但目前只能启动、检查环境，并在条件不足时拒绝任务。上一轮实现没有完成底盘实机互锁，不能把模拟测试通过当成整机已经打通。

本次重新核对的机载配置仍是：

- `authority_socket: null`：没有接入底盘与机械臂的独占互锁。导航速度仍停留在内部话题，没有接到底盘。
- `travel_joint_deg: null`：没有确认适合底盘移动的机械臂姿态；也没有实现经过验证的自动姿态切换。
- 上次无运动检查中，CAN 一度正常，随后驱动报 `can0 is loss`，相机也发生 USB 重连；需要先确认连接稳定。

因此，现在按第 2～4 节做环境检查即可。**第 5 节是接口接通并完成现场验收后的操作顺序，当前不要把它当成可完成抓取的步骤。**

## 2. 登录与检查 CAN

在开发电脑登录：

```bash
ssh unitree@192.168.31.22
```

进入主工程：

```bash
cd /home/unitree/A2_loco_manipulation
ip -details -statistics link show can0
```

应看到接口 `UP`、`bitrate 1000000`；CAN 的 `ERROR-ACTIVE` 是正常工作状态名称，不是报错。

如果接口存在但为 DOWN，且现场确认硬件已连接，可执行：

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
ip -details -statistics link show can0
```

sudo 如提示密码，需要在终端输入。已经 UP 且为 1 Mbps 时跳过配置，不要为了重复设置而先关闭 CAN。接口不存在、BUS-OFF 或频繁丢失时，先检查供电、USB/CAN 接头及线缆。

**CAN 为 UP 不等于机械臂反馈正常。** 后面还必须检查驱动与关节反馈。以上命令本身不使能电机、不发送关节目标。

## 3. 一条命令启动环境

```bash
./a2ctl up
```

它后台管理相机、项目导航感知与目标管理、ROS 桥接，以及原 ROS2 single_view 抓取流程。启动不会导航、使能电机或抓取，也不设置开机启动。SSH 断开后后台进程仍保留。

不要同时启动旧 `single-pick-session.py`、手动 single_view、preview-start 或另一套相机／机械臂驱动。若报已有组件冲突，先确认原进程由谁启动、是否持物，再由原入口处理；不要批量 pkill。

查看状态：

```bash
./a2ctl status
```

重点看：

- `environment_ready`：组件检查是否通过，不能只看进程 `running`。
- `components.arm.errors`、`components.nav.errors`：正常应为空。
- `components.arm.effective_tcp`：必须是 `[0.0, 0.0, 0.105]`。
- `components.arm.executor`：待机时通常为 `WAITING_FOR_PREGRASP`。
- `components.nav.status`：待机时为 `idle`。
- `components.nav.stopped`：连续速度反馈和导航零指令是否满足停止条件。
- `ready`、`blockers`：真实任务是否具备条件，以及具体缺项。

当前即使 `environment_ready=true`，仍会因互锁和行走姿态缺失而 `ready=false`。`up` 返回码 3 表示未就绪，不是可以忽略的成功提示。

`up` 不会自动摆好机械臂。目前记录的观察姿态为 J1～J6 `[0,0,0,0,5,0]°`、夹爪 75 mm；它不等于已经确认的安全行走姿态。不要在统一驱动运行期间另用 SDK 姿态脚本抢占 CAN。

## 4. 现在如何结束检查

如果没有提交任务、没有持物或恢复锁：

```bash
./a2ctl down
./a2ctl status
```

down 接收请求后会逐个关闭本入口拥有的进程，稍后 status 应显示 `supervisor: down`。它不关闭其他入口的底盘服务，不自动松爪或回零，也不把 CAN 接口设为 DOWN。

## 5. 接通实机接口后的操作顺序（当前未开放）

只有控制权互锁、行走姿态、停止反馈和现场低速验收均完成后，才使用本节。仅修改配置、填入随意关节角或伪造许可不能代替这些工作。

先完成第 2、3 节。将瓶子放在相机可识别、深度有效且机械臂可达的位置；第一次端到端验收建议视野中只放一只瓶子。确保运动区域无障碍，现场能操作硬件急停。

### 5.1 第一段：靠近瓶子，停住等待

```bash
./a2ctl run --task-id bottle-20261028-001 --goal bottle --timeout 180
./a2ctl status
```

`bottle` 是项目已有的瓶子目标配置，不是地图坐标，也不是固定向前走几秒。现有算法停车参考是相机光学 Z 约 0.54 m：`stop_distance=0.52` 加 `distance_tolerance=0.02`。它不是狗中心距瓶子的距离，也不是已验证的制动距离。

第一段到达并验证停稳后，状态进入 `AWAITING_PICK`，此时不会自动抓取。你确认到位后，使用**同一个任务 ID**显式开始第二段：

```bash
./a2ctl pick-once --task-id bottle-20261028-001
./a2ctl status
```

第二段不重新导航。它重新检查停稳和观察姿态，然后获取新数据、规划并抓一次。等待你的指令也计入第一段 `--timeout 180` 的总时限；超时进入恢复状态，不自动执行。第二段命令不会延长这个时限。

此入口不保证在任意环境里自主找到瓶子；没有有效稳定目标时应失败退出。不能将内部导航计算或 `reached` 状态当成真实底盘已经到位。

命令返回 `accepted` 只表示接收请求。用 status 持续查看任务阶段。流程应依次检查环境、控制权、行走姿态、导航结果、连续实测停稳、抓取观察姿态、新 RGB-D 数据、新规划，再使能并执行一次抓取。

当前实现只检查姿态，不会自动从行走姿态变到抓取观察姿态；不符即停止。最终不自动返回、不重试、不放置、不回零。

### 5.2 已经到位时只抓一次

```bash
./a2ctl pick-once --task-id bottle-20261028-002 --timeout 120
./a2ctl status
```

这也要求底盘互锁和连续停稳证据；**不是绕过互锁的手动抓取命令**。当前同样不能放行。

每个新任务使用新 ID。同一 ID 的 run 重复提交不重做靠近；仅在 AWAITING_PICK 时，同一 ID 的 pick-once 可以继续第二段，第二段也只执行一次。换 ID 不能绕过当前任务、持物或恢复锁。

### 5.3 判断结果

- `HOLDING`：执行器报告持物保持。查看接触证据并现场确认瓶子；不能仅凭此状态认定已确认抓住。
- `RECOVERY_REQUIRED`：需要现场恢复，保留原因，不重复启动。
- `FAILED`、`TIMEOUT`、`CANCELLED`：停止本轮，不自动重试；检查中止确认和实际姿态。
- 仍为执行阶段或通信失联：结果未知，不能当成功或安全停止处理。

TCP 保留 10.5 cm，不改回 11.5 cm，也不降低接触阈值来让任务显示成功。

## 6. 中止与下一轮

对本入口提交的任务请求中止：

```bash
./a2ctl abort
./a2ctl status
```

分别检查导航和抓取的确认结果。软件中止不等于物理急停；紧急情况使用现场硬件急停。按 Ctrl+C 退出状态查看不会停止机器人。

持物、失败或结果未知时，不要直接 down、重启驱动或删除锁。先现场处理物体与故障，并确认底盘和机械臂停稳。反馈仍在线时，可记录已完成的恢复：

```bash
./a2ctl recover --task-id bottle-20261028-001 --note '现场已处理物体，夹爪无物，机械臂及底盘停稳，故障原因已处理'
./a2ctl down
./a2ctl up
```

把 ID 换成真实上一轮任务 ID；说明必须反映实际情况。recover 不会代替你松爪、移动机械臂或排除故障。反馈离线或进程崩溃后无法确认状态时仍会拒绝；需要工程人员检查，不提供删除 state.json 强制解锁的操作。

## 7. 出问题看哪里

```bash
cd /home/unitree/A2_loco_manipulation
./a2ctl status
tail -n 80 data/logs/unified/supervisor.log
tail -n 100 data/logs/unified/single-view.log
tail -n 80 data/logs/unified/object-navigation.log
```

`state.json` 保存任务与恢复锁，`events.jsonl` 保存阶段变化。不要修改它们来重试。

- `CAN_NOT_READY`：检查第 2 节。
- `can0 is loss` 或机械臂反馈 stale：先处理连接，不能只重新 up。
- 相机 USB 错误／反复重连：检查连接和供电，重新确认连续数据。
- `CONTROL_AUTHORITY_UNAVAILABLE`：实机互锁尚未接通，不是相机放置错误。
- 行走姿态未配置或观察姿态不符：需要确认姿态，不能随意填数。
- 旧观测／规划失败：禁止执行；不要直接手动调用 task/start 绕过检查。
