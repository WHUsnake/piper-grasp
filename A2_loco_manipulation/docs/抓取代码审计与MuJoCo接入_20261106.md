# 抓取源码问题与 ROS/MuJoCo 接入记录

目标：用主工程的感知、候选、规划和执行代码，在固定站立 A2 + PiPER 的 MuJoCo 场景中实现瓶身中段、有效夹持区抓取及抬升保持。不是只重放旧独立 IK 脚本的成功录像。

## 已确认的问题和处理

1. **源码交付不完整。** A2 当前顶层只有候选包，planner/executor/感知完整源包缺失，launch 又引用这些包。已从已审计本工程快照恢复维护源，原哈希与路径记录在 `data/graspnet/maintained_source_provenance.json`。没有把历史快照或 install 目录当作修改源，也没有声称已修改机载部署。
2. **抓取坐标和夹持位置。** 原生 GraspNet +X 进近不能直接当工具 +Z；TCP 与有效夹持面也不是同一个点。共享 `grasp_generation/refinement.py` 从目标点云拟合直立瓶身中部，将其对齐模型 link6 +Z 0.105 m 的夹持面中点，TCP 仍由参数配置。原始网络方向和位置修正量保留。平行夹爪增加绕进近轴 180° 的等价表示供 IK 选择，没有将抓取方向替换成固定模板。
3. **原 planner 只检查预抓取。** 预抓取可达并不保证能接近、闭合和抬升。现已增加 MoveIt IK、OMPL 预抓取路径、全程避碰的 Cartesian 进近/抬升；fraction 必须 >=0.999，部分路径明确拒绝。桌面、桌腿、自碰撞和点云拟合瓶身纳入检查，抬升规划使用附着瓶子和限定手指 touch links。
4. **参数在 planner/executor 之间丢失。** 单独 PoseStamped 不能传递整套选中结果。新增 SelectedGrasp，包含会话、候选、三个位姿、开口/距离、三段轨迹和目标几何；仿真执行器消费同一条消息和同一组轨迹。预抓取规划的手指开口状态与所选开口一致，不拿 70 mm 的避碰结果直接执行更窄的开口。
5. **执行器可能没有走规划路径。** 原执行器主要重复发送 PosCmd，规划通过不等于控制器跟随规划。新的仿真分支使用 FollowJointTrajectory 执行检查过的轨迹，MuJoCo 反馈实际关节、位姿和接触力。**实机 PosCmd 分支仍不能当作轨迹跟随验收**，默认 execute=false，并拒绝缺少完整选择、过期或 preview-only 的候选；没有为了仿真成功开放实机。
6. **数据失效和时序缺口。** 无检测、输入过期等分支原来直接返回。现在显式输出无效状态/空候选，候选缓存过期清空。保留采集时间；规划期间允许固定任务快照，但执行前必须收到新鲜观测、复核目标中心/半径/高度、会话和起始关节。复核对象是物体，不是要求神经网络重复输出同一角度类别，避免稳定物体因候选抖动被误判。
7. **状态机成功可能高估实际抓住。** SDK effort 或 HOLDING 单独不能证明物体离桌。在 MuJoCo 侧独立记录实际抬升、双指接触、指尖余量和接触高度；没有焊接约束或直接覆盖瓶子位姿。实机仍需真实持物证据，不能用仿真对象状态代替。
8. **旧网页结果容易与主链路混淆。** 网页新运行入口已经切换至 ROS 主链路。metrics.pipeline 必须是 `ROS2_YOLO_GraspNet_MoveIt_TaskExecutor`；历史独立脚本结果明确标注。新链路使用实际 YOLO 掩膜，不使用 MuJoCo 物体 ID 分割。

## 不能据此宣称已解决的问题

- 现有实机底盘独占/停稳互锁、行走安全姿态和机载运行前缀需要现场确认，本次没有解锁或绕过。
- CAD 安装位置、真实手眼标定、TCP、夹爪有效接触区、SDK effort 的量纲和阈值仍需实测。仿真 0.105 m 夹持面和当前 TCP 参数不等于实机标定结果。
- 当前几何适配针对直立近似圆柱水瓶；未验证倒瓶、任意物体、真实透明瓶深度缺失和杂乱场景。
- 当前 MoveIt 场景包含已建模桌子和目标，不等于自动重建了所有环境障碍物；真实场景更新、附着物误差和在线跟踪偏差需要进一步验证。
- 实机分支仍使用原 PosCmd 接口，不具备本次仿真 FollowJointTrajectory 分支的路径跟随证明。未获现场放行前保持关闭。
- 本机 MoveIt 2.5.9 在停止后的析构阶段出现 SIGSEGV，日志与退出码保留。它不影响已采集的物理结果，但属于未解决的环境稳定性问题，不能当作无人值守部署已验收。
- 原独立仿真通过的参数，可能不能通过现在的完整 MoveIt 路径检查。当前自定义 55 cm / 左移10 cm / 桌高85 cm / TCP8.5 cm 试验出现过进近路径不完整，系统拒绝执行而非沿用旧成功结果；不保证所有滑条位置都能抓取。

## 低桌面失败复核与运动平顺改进

截图参数为 X=0.60 m、Y=0、桌面=0.64 m、TCP=0.095 m。`simulation/ros_pipeline/low_table_diagnosis01/` 对每个候选使用当前姿态和三组不同肘部种子，均返回 -31；关闭避碰的额外诊断查询也返回 -31。该诊断结果不会送入规划或执行。此结果只能证明当前候选与搜索预算下没有找到解，不能证明所有姿态绝对不可达。

对照最初的独立多初值 IK 仿真，`simulation/ros_pipeline/low_table_independent_compare/` 同参数也返回 no_reachable_candidate；记录中的预抓取位置残差约 17–25 mm，部分抓取姿态还有约 5–10 度角度残差。不能通过放宽误差把它包装成成功。默认场景成功不代表低桌面同样可达。

源码增加了多初值、IK 搜索诊断，以及 MuJoCo 轨迹的余弦缓起停时间缩放。后者沿原有已检查的分段关节路径推进，不改变路径、不提高原轨迹速度，每段动作增加至多 0.3 秒。它改善动作边界的突变，但不等于全轨迹 jerk/加速度有界认证，也不能解决不可达位姿。对应路径、种子保留、诊断不执行的单元测试已添加。

缓起停版本完整物理回归见 `simulation/ros_pipeline/smooth_motion01/`：最低保持抬升 0.102253 m，双指接触比例 1.0，实际指尖余量约30 mm，网页成功样例已更新。14项 pipeline 合约测试通过。

## 根因修正：原环境低桌面抓取成功

此前“当前候选无 IK 解”的结论不能推出“这个环境抓不到”。固定 X=0.72 m、Y=0、桌高0.59 m、TCP0.095 m，方向扫描发现水平/略向下姿态可达，向上倾斜的姿态会触及第5关节下限。原适配器只保留网络方向并增加平行夹爪翻转，不能覆盖同一瓶身的可达进近方向。这是候选适配及搜索覆盖问题，而不是技术路线必然失败，也不是要求用户改变环境。

修复：针对目标点云确认的直立近似圆柱体，在共享 refinement 模块中增加沿网络水平进近方位的几何适配候选，进近仰角取0/-10/+10/-20度，闭合轴保持水平；改变方向时同步重新计算 TCP，使实际夹持面中心保持不变。原网络方向和来源保留，新增方向标记为 orientation_adaptation，不冒充原始网络预测；沿用的分数仅代表其父网络候选。模拟配置显式启用 orientation_search，实机默认配置不自动启用。所有新候选仍经过 IK、机器人/桌子/目标避碰、完整进近与附着抬升规划及物理接触验证。

证据 `simulation/ros_pipeline/low_table_fixed01/`：原参数不变，原始方向及180度夹爪表示均返回-31；水平适配候选 index2 通过 IK、OMPL、100% Cartesian 接近和抬升，最低保持抬升0.0984724 m、双指接触1.0、实际接触指尖余量0.0238724 m。无焊接、无物体位姿覆盖、实际YOLO掩膜。15项pipeline测试通过，包含新候选正交性、夹持中心不变与原网络证据保留。

此修复使用已验证的直立瓶身几何先验，尚不能推广为任意物体抓取保证。MoveIt退出析构崩溃仍是独立的未解决环境问题。

网页API同参数再次验证成功，记录 `simulation/a2_table_grasp/runs/926d4fd92c3e48c899e1aea23f1faf52/`：最低保持抬升0.099608 m、双指接触1.0、指尖余量约25.93 mm，网页当前结果已切换至这次运行。

此前失败的另一组 X=0.60 m、桌高0.64 m 也在原环境完成回归，记录 `simulation/ros_pipeline/low_table_fixed02/`：-10度适配候选通过完整规划，最低保持抬升0.102158 m、双指接触1.0、指尖余量约30 mm。没有通过调整环境修复。

## IK/MoveIt优化及批量回归（持续更新）

本轮不改变用户环境。初版多方向/抬升优化批量测试在 `simulation/ros_pipeline/ik_moveit_regression01/` 留下完整记录：默认、低桌、近低桌、左右偏移5项物理成功；79 cm/73 cm两次虽规划通过却在接近时碰倒瓶子，执行器拒绝进入抬升。不能把这轮计为7项成功。

进一步逐点正运动学检查该失败样本：返回接近轨迹80个点，相邻关节变化最大0.12 rad，但第6关节由约-3.13走到+3.10，中间工具方向最大偏离目标3.09 rad。因此fraction=1与小关节步长不能证明工具保持目标方向。先前只检查fraction/跳变缺少了对返回轨迹几何的复核。

现已加入：GetPositionFK逐点核验方向误差<=0.03 rad、偏离要求直线<=3 mm；逐点GetStateValidity核验重采样后的碰撞状态；0.25 rad相邻关节绝对步长守卫。瓶身几何搜索统一夹爪表示，避免网络随机手指符号把直接候选推到第6关节正负pi附近，等价翻转保留为后备。当前完整回归在 `simulation/ros_pipeline/ik_moveit_regression02/`，以其最终results.json为准。

另外增加了候选去重、网络/径向/中间方位覆盖、直接抓取优先、32候选预算；适配方向采用拟合半径决定预张开宽度，超夹爪能力拒绝；仿真在竖直抬升失败时验证4/8 cm回收抬升路径。实机默认仍关闭仿真执行入口与回收抬升配置。


最终复核汇总见 `simulation/ros_pipeline/ik_moveit_regression02/validation_summary.json`：默认首次因未取得新鲜观测拒绝执行，保留该失败；候选去重向量化提速后默认复测成功，未放宽时间戳。按每个案例最新结果，6种场景加79 cm重复共7项均完成物理抓取，最低保持抬升8.326–10.045 cm、双指接触比例1.0。覆盖距离60/72/79 cm、桌高59/64/73/76 cm、横向0/±10 cm的选定组合，不是这些参数所有笛卡尔组合、更不是整个滑条范围的保证。

19项pipeline合约测试、12项GraspNet测试、11项几何/网页参数测试通过。返回轨迹终点还需达到要求位置3 mm以内。源码最终哈希另存final_source_sha256.json；先前版本的失败记录没有覆盖。MoveIt退出析构SIGSEGV仍未解决，真实机器人未启用。

最终网页入口再次完成79 cm /73 cm物理验证，记录 simulation/a2_table_grasp/runs/911b0d23d682476d8af675be16a6ca48/：success=True、最低保持抬升0.099721 m、双指比例1.000。网页当前结果已指向此运行。


## 扩展不同距离/高度/偏移的后续优化

源代码增加：实际夹持端点IK优先，并以该解求预抓取，减少从零位误选不连续分支；缓存同一候选端点解，端点失败不重复尝试不同预抓取距离；预抓取后退备选6/14 cm；瓶身夹持高度备选观测高度40%/60%；仿真回收抬升最大12 cm；总搜索预算90秒。TCP和实际夹持面中心的对应关系、实际目标身份/新鲜度、完整路径、逐点FK与碰撞复核、接触门槛均保留。默认实机参数仍只有原预抓取距离和竖直抬升，模拟参数显式启用扩展搜索。

扩大范围基线 `simulation/ros_pipeline/workspace_baseline01/` 与修改后 `workspace_optimized01/` 对照：55 cm距离/85 cm桌面、左右20 cm偏移、低桌加偏移、高桌加偏移均物理成功；85 cm距离/65 cm桌面两版都失败。新版本将后者准确定位到32个实际夹持端点IK均未找到解，而不是仅报告接近路径fraction不完整。额外模型方向/高度扫描也未找到精确解，但这不是数学上证明所有姿态不可达。不能声称本轮把扩展组成功率由5/6提高到了6/6。

原场景回归 `workspace_standard01/` 的default/low/far/far_repeat四项均物理成功。边界低桌测试 `workspace_edge01/` 单独保留，最终以各目录results.json为准。候选搜索失败、观测失效与实际执行失败都保留，不更换环境制造成功。

网页失败提示按阶段归类，夹持端点无解会说明“当前候选未找到满足约束的位姿”，不声称已证明不可达；详细原始错误仍在每次run日志中。相关20项pipeline、13项几何/网页及12项GraspNet测试通过。


边界低桌的55 cm/50 cm两项均物理成功，最低保持抬升分别10.20/10.24 cm。后续又修正搜索调度为每4个方向一组、组内轮流尝试不同预抓取距离，防止较短进近被大量10 cm尝试饿死；对应单元测试新增，pipeline合约测试现为21项，总相关测试46项。

网页入口 `simulation/a2_table_grasp/runs/14c15024922449489ae6c50b66c452c8/` 使用最终调度：65 cm距离/55 cm桌面下，前4个10 cm预抓取均无解，第5次使用同一候选的6 cm预抓取，完整规划与物理抓取成功，最低保持抬升10.019 cm、双指接触比例1.0。预抓取距离在消息、轨迹、网页幽灵夹爪和数值显示中一致。
