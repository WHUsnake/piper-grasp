# 机械臂抓取与放置架构

本分支聚焦网页选点抓放。按现有模块划定职责，保留已验证执行路径；不在发布整理时
同时改写控制器、物理参数或任务协议。当前网页放置协议为 v4。

## 代码入口与职责

### 网页交互

`integration/integration/static/go2/grasp.js` 负责腕部 RGB-D 取图、像素选点、
抓取／放置提交、状态展示、恢复入口和用户发起的浏览器录屏。
`index.html`、`style.css` 定义面板；`app.js` 维护场景显示和行走输入。
浏览器不判断夹住没有、不计算机器人轨迹、不把零接触力判为掉落。

### HTTP 与唯一任务状态

`integration/integration/viewer.py` 接收网页请求、管理物理进程通信，不生成抓取姿态。
`go2_grasp.py` 的 `GraspPanel` 管理任务子进程、请求新鲜度、错误归并和可操作状态。
`/api/grasp/status` 中 `task.state`、`task.allowed_actions` 是阶段及权限的唯一合同；
网页仅叠加网络连接、正在提交和是否已有选点等本地条件。

`GraspWorld` 管理世界会话、任务所有权、持物状态、轨迹执行和恢复。
子进程必须携带正确的 owner/session；刷新页面不释放持物、不重放任务。
运行中失败与未持物的可恢复失败分别处理；已释放但视觉结果不明不应继续占着机器人。

### 感知与持物几何

`go2_grasp.py` 的 `placement_surface`、`reobserve_placement`、`placement_visual_result`
分别负责腕部深度支撑面／空闲区域测量、世界目标重投影和放后可见几何检查。
`go2_grasp_ros.py` 对接 RGB-D 目标分割，并在抬升前绑定瓶底偏移和直立轴。
底面由邻近观测桌面推断，假设物体起初为直立刚性瓶。

机身相机虽然保留模型内部名 `body_rgbd`，实际接口是 RGB、`depth=null`，只供观察。
不可从它产生三维抓放点。任何新感知后端必须明确像素、米制深度、时间戳、
相机内参及采集时坐标变换；不能把相机移动前的像素当作新帧目标。

### 规划与编排

抓取由 `go2_grasp_ros.py` 适配配置中的 A2 源码的感知、GraspNet／GraspGenX、
`robot_planner` 和 `task_executor`。MoveIt 负责可达、关节限位、碰撞和完整接近／抬升规划。
两套模型各自生成候选，共用 11 cm TCP、候选适配、MoveIt 和执行链路。`launch_pipeline`
在运行目录记录请求与算法指纹；目前仍每次创建抓取进程，尚未实现常驻。
网页 TCP 读取 `config.local.json` 的 `go2_grasp.tcp_m`（默认 0.11 m），抓取转换和规划
使用同一请求值；候选到指尖的偏移从本次仿真几何审计值计算。瓶体精修保留机器人径向
方向搜索，移除了对世界坐标 X 正方向的固定门槛，最终仍需通过 MoveIt 可达和碰撞检查。
每次抓取的 `grasp-screening.jsonl` 逐帧记录输入点数、模型输出、宽度／姿态适配、
几何／朝向筛选、最终发布数量及失败原因；`grasp-screening-summary.json` 汇总首帧等待、
推理／后处理时间和 MoveIt 拒绝阶段。两套后端的计时必须以相同场景和新鲜 RGB-D 比较。

`tcp-geometry-audit.json` 在每次抓取前核对导出的仿真 URDF 和算法几何：当前 link6→TCP
为 0.110 m，算法指垫中心 0.105 m，指尖 0.13503 m。这个检查只证明仿真模型内部一致，
不代表真机已标定。真机需实测 link6 坐标系至两指接触中心的三维变换和闭爪接触开度，
将测量值同时写入适配、规划与执行配置，再用已知工装点复核。

放置由 `go2_grasp.py` 的 `run_place` 编排，`integration/mtc_place/src/place.cpp`
通过 MTC 规划接近、撤离和回零。规划返回轨迹，不直接改 MuJoCo 状态或控制夹爪。
最终靠近不交给开环长距离下降轨迹。

### 执行与仿真适配

`GraspWorld.tick_visual_place_control` 在物理循环内执行有界小步几何修正、直立方向校正及
松爪阶段手腕位姿保持；单步不超过 3 mm，释放前约 6 mm 几何间隙。
松爪开始后不再假设瓶底与手腕保持刚性关系。网页选择 `wrist_rgbd_geometry`，
不使用旧支撑力接口决定何时下降或松爪。旧接触控制仅保留诊断／兼容用途。

`arm_trajectory.py` 校验轨迹；`go2.py` 执行积分子步；`go2_piper.py` 装配仿真资产；
`viewer.py` 协调步前控制和步后数值检查。数值异常保留故障及检查点。
当前瓶体各 0.13 kg、指垫摩擦 `[0.4, 0.005, 0.0001]`；发布整理不调整它们。

### 部署、资源和源码来源

用户入口统一为 `bin/lab`，`lab/go2_grasp.py` 配置算法路径与消息构建，
`lab/deployment.py` 管理本工作区进程，`profiles/hssd-go2-piper.json` 保存场景和姿态配置。
`grasp-source/manifest.json` 锁定本分支算法快照；`manifests/sources.lock.json` 锁定外部基础仓库。
两者职责不同，不把未发布的本地算法改动假称为上游提交已有的内容。

## 正常流程

- 抓取：新腕部 RGB-D → 选物体 → 分割／候选 → MoveIt 完整规划 → 接近 → 闭爪 → 抬升 → 保持夹持回零。
- 放置：新腕部 RGB-D → 选桌面空位 → 平面／区域检查 → MTC 接近 → 几何／直立修正 → 保持手腕松爪 → 完整撤离 → 回零 → 新深度连续检查。
- 失败：停止当前危险动作 → 后端报告失败阶段及允许操作 → 有效持物时重新选点；无持物且条件允许时归档恢复；显式恢复初始状态会结束当前场景。

## 信息依赖与验收缺口

抓取确认、滑落保护、持物门槛仍使用 MuJoCo 物体／接触状态；碰撞场景和世界位姿也有
仿真来源。v4 仅末段几何放置不以物体接触力为决策输入，不能称整个平台为纯视觉或真机就绪。
腕部目标出视野时沿用最后观测静态桌面；无真实力传感器，不能宣称受力确认支撑。
视觉结果检查在遮挡和拥挤时可能不能确认物体身份，持物偏移也无法感知未观测滑动。
现有深度分割要求至少 100 个有效目标深度像素、可见高度至少 6 cm，选点像素也要有有效深度。
真机透明瓶与夹爪遮挡可能只有少量瓶盖像素有深度；不能将缺失区域当作瓶子消失、
也不能宣称整瓶可见。真机适配需融合 RGB 轮廓、可测桌面平面、稀疏可靠深度和多帧观测，
给目标位姿置信度；若仍不可判定，应保持夹爪并报告证据不足，而非输出持物成功或掉落。

当前在线成功范围为本机直立蓝瓶和固定桌面；不以旧版成功替代 v4 验收，不承诺未知物体成功率。
详细在线证据索引见 `validation.md`。模型、环境、构建、录屏和运行记录在外部工作区；
除已授权固定 LFS 场景资源包外，不把这些数据作为源码上传。
